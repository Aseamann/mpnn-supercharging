## What you should look at, in order

### 1. The notebook had never been executed as a notebook

This is the one finding that changed a claim rather than a file.

All 26 code cells were stored with `execution_count: null` and zero outputs.
The standing claim that they "run clean" rested on `analysis_lib` having been
called directly, not on a top-to-bottom run. The cause: `py311` has IPython but
no jupyter, nbconvert, nbformat or ipykernel.

```
$ jupyter nbconvert --to notebook --execute analysis.ipynb
timeout: failed to run command 'jupyter': No such file or directory
```

Both `README.md` and `run_all.sh` gave that exact command as the reproduction
step. The one instruction a reader would follow to regenerate every figure
failed immediately.

**The claim itself turned out to be true.** It is now demonstrated two ways,
after you pointed at `shared_als515`:

| Route | Env | Result |
|---|---|---|
| `jupyter nbconvert --to notebook --execute` | `shared_als515` | 35 s, exit 0, no cell errors |
| `python scripts/run_notebook.py` | `py311` | 26/26 cells, 11 to 21 s |

`shared_als515` has jupyter 5.8.1, nbconvert 7.16.6, ipykernel 6.30.1, numpy,
pandas and matplotlib. It has no torch and no PyRosetta, so it cannot run any
other phase, but the notebook only reads CSVs. I did not install anything into
`py311`, per the standing rule that only DSSP and TM-align go there.

### 2. Cross-environment reproducibility, unplanned but worth having

Running the notebook under both envs and diffing the outputs:

**All seven table CSVs are byte-identical.**

| | `py311` | `shared_als515` |
|---|---|---|
| Python | 3.11.8 | 3.13.5 |
| numpy | 1.26.4 | 2.3.1 |
| pandas | 2.2.1 | 2.3.3 |

No analysis number depends on those versions. This is a usable sentence for the
response letter if a reviewer asks about reproducibility. The figures and tables
in the repository were written from `py311`, and they are now written by the
notebook run itself rather than by a side script, so their provenance is the
notebook.

### 3. Three things left open for you to decide

None of these blocks anything. None was changed unilaterally.

**a. `logs/mpnn/` is 21 MB of the 36 MB first commit.** 456 per-cell
ProteinMPNN stdout logs, 58% of everything that would be staged. They are
regenerable output of the same kind as `logs/slurm/`, which `.gitignore`
already excludes, and `results/cells/*.json` carries the per-cell provenance
independently. Section 14 does not name `logs/mpnn/`, so the checklist passes
as written. Excluding it is a one-line `.gitignore` change, but it changes what
gets published, so it is your call.

**b. `fold_class` is null on the 408 eGFP rows of `designs.csv`.** eGFP enters
as the focus scaffold, not through CATH curation, so it was never
DSSP-classified; its manifest row carries `is_focus=True` and
`source_split=focus_egfp`. Fold-class figures describe the 24 curated scaffolds,
with eGFP in the eGFP-specific panels. Filling it in would mean either running
eGFP through the Section 4 classifier, which changes what F1 and T1 report, or
writing a class by hand, which rule 4 forbids.

**c. AvNAPSA `nstruct` is still open**, unchanged from before this pass. It
changes the frozen design matrix, so it waits for an instruction. Until then
`n_unique_mutation_sets` on that arm is not measured, and must not be reported
as 1.

Two further items are already tracked and unchanged: `MANUSCRIPT_CHECKLIST.md`
is unapplied by design, since the manuscript is outside `Benchmark/`, and
**nothing is committed to git**. `Benchmark/` is still one untracked directory
of about 2,754 files.
